# Includes

The JSON:API `include` parameter lets clients request related resources in the same response, avoiding N+1 requests.

## Defining Allowed Includes

By default, `allowedIncludes()` returns the keys from your `relationships()` definition:

```php
use BlueBeetle\ApiToolkit\Resources\Resource;

class OrderResource extends Resource
{
    public function relationships(): array
    {
        return [
            'customer' => CustomerResource::class,
            'items'    => OrderItemResource::class,
        ];
    }

    // allowedIncludes() defaults to ['customer', 'items']
}
```

Override it to restrict which relationships can be included:

```php
use BlueBeetle\ApiToolkit\Resources\Resource;

class OrderResource extends Resource
{
    public function allowedIncludes(): array
    {
        return ['customer']; // items cannot be included
    }
}
```

## Usage

```
GET /api/orders?include=customer
GET /api/orders?include=customer,items
GET /api/orders?include=items.product         → nested include
```

## Response Structure

When includes are requested, related resources appear in the `included` array:

```json
{
  "data": {
    "type": "orders",
    "id": "1",
    "attributes": { "total": 150.00 },
    "relationships": {
      "customer": {
        "data": { "type": "customers", "id": "42" }
      }
    }
  },
  "included": [
    {
      "type": "customers",
      "id": "42",
      "attributes": { "name": "John Doe" }
    }
  ]
}
```

Included resources are automatically deduplicated. Each unique type/id pair appears only once, even if multiple records reference the same related resource.

## Validation

A list built with the `QueryBuilder` checks `include` against its allowed includes (the builder's `allowedIncludes()`, else the resource's). An include outside them is refused with a 422 instead of being ignored, and a list that allows none refuses any include:

```
GET /api/orders?include=secret               → 422 "The [secret] is not a valid include value."
```

A single-record endpoint doesn't go through the `QueryBuilder`, so its form request names the includes it allows, and the toolkit checks `include` against them:

```php
use BlueBeetle\ApiToolkit\Http\Requests\FormRequest;

class ShowOrderRequest extends FormRequest
{
    public function allowedIncludes(): array
    {
        return ['customer', 'items'];
    }
}
```

`allowedIncludes()` returns `null` by default, which leaves `include` to the request's own rules, so a request can still validate it its own way with the [`ValidInclude`](/docs/api-toolkit/latest/advanced/validation-rules) rule in `queryParamRules()`.
