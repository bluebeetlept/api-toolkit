# Pagination

The toolkit supports two pagination strategies: offset-based and cursor-based.

## Offset Pagination

Traditional page-number pagination. Use `->paginate()` on the query builder.

```php
use App\Http\Resources\ProductResource;
use App\Models\Product;
use BlueBeetle\ApiToolkit\QueryBuilder;
use Illuminate\Http\Request;

class ProductController
{
    public function index(Request $request)
    {
        return QueryBuilder::for(Product::class, $request)
            ->fromResource(ProductResource::class)
            ->paginate();
    }
}
```

### Query Parameters

```
GET /api/products?page[number]=2&page[size]=20
```

### Response Meta

```json
{
  "data": [...],
  "meta": {
    "page": {
      "currentPage": 2,
      "lastPage": 5,
      "perPage": 20,
      "total": 100
    }
  },
  "links": {
    "first": "...",
    "last": "...",
    "prev": "...",
    "next": "..."
  }
}
```

## Cursor Pagination

More efficient for large datasets. Use `->cursor()`.

```php
use App\Http\Resources\ProductResource;
use App\Models\Product;
use BlueBeetle\ApiToolkit\QueryBuilder;
use Illuminate\Http\Request;

class ProductController
{
    public function index(Request $request)
    {
        return QueryBuilder::for(Product::class, $request)
            ->fromResource(ProductResource::class)
            ->cursor();
    }
}
```

### Query Parameters

```
GET /api/products?page[size]=20
GET /api/products?page[cursor]=eyJpZCI6MjB9&page[size]=20
```

### Response Meta

```json
{
  "data": [...],
  "meta": {
    "page": {
      "perPage": 20,
      "hasMore": true
    }
  },
  "links": {
    "prev": "...",
    "next": "..."
  }
}
```

The cursor value is opaque to the client. They should use it as-is from the `links.next` URL.

## Configuration

In `config/api-toolkit.php`:

```php
'pagination' => [
    'default_size' => 20,     // Default items per page
    'max_size'     => 100,    // Maximum items per page (requests above this are capped)
    'valid_sizes'  => [10, 20, 40, 80, 100],
],
```

Without validation, a page size greater than `max_size` is silently capped and a size below 1 is clamped to 1.

## Validation

When the controller type-hints the toolkit's [`FormRequest`](/docs/api-toolkit/latest/advanced/form-requests), `page` is validated for you, with no rules to write:

| Key | Rule |
|---|---|
| `page` | Must be a set (`page[number]=2`, not `page=2`) |
| `page[number]` | An integer, 1 or more |
| `page[size]` | One of `valid_sizes` ([`ValidPageSize`](/docs/api-toolkit/latest/advanced/validation-rules#validpagesize)) |
| `page[cursor]` | A string |

```php
use BlueBeetle\ApiToolkit\Http\Requests\FormRequest;

class ListProductsRequest extends FormRequest
{
}

class ProductController
{
    public function index(ListProductsRequest $request)
    {
        return QueryBuilder::for(Product::class, $request)
            ->fromResource(ProductResource::class)
            ->paginate();
    }
}
```

```
GET /api/products?page[number]=2&page[size]=20    → 200
GET /api/products?page[number]=0                  → 422 (below 1)
GET /api/products?page[size]=15                   → 422 "The [15] is not a valid page size value."
GET /api/products?page=2                          → 422 (not a set)
```

To offer other sizes everywhere, change `valid_sizes` in the config. For one endpoint, declare `page.size` in `queryParamRules()`; a request's own rule replaces the built-in one:

```php
use BlueBeetle\ApiToolkit\Http\Requests\FormRequest;
use BlueBeetle\ApiToolkit\Rules\ValidPageSize;

class ListMovementsRequest extends FormRequest
{
    public function queryParamRules(): array
    {
        return [
            'page.size' => [new ValidPageSize([50, 200, 500])],
        ];
    }
}
```

A controller that takes a plain `Illuminate\Http\Request` gets no validation: bad values are capped or clamped as described above.
